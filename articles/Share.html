如何用c++写一个桌宠
注：这是一个以学习为目的进行的项目，其中大部分代码由ai编写，本人不享有知识产权 1.选择你喜欢的ide，配置编译环境。推荐使用 Visual Studio，可以自动配置你所需要的一切 下载地址：https://visualstudio.microsoft.com/zh-hans/downloads/ 2.需要点击“创建项目”或打开文件夹，写代码应当避免单文件编写 3.需要在项目开始前就做好规划，可以先写个文档用来指导整个项目的未来发展： （这里还有一篇AI写的文档，写的更好，需要逐步学习） # 项目目标 1.设计一个桌宠系统，包含基本的点击交互、定时行为等功能，不包含网络功能与复杂ai系统 窗口为铺满用户显示器的形式，为后续补充做准备，需要加入各种越权影响用户体验的meta要素 2.包含四个层级的模块：Core（基础库）、Systems（系统层）、Runtime（协议层）、Engine（引擎层）、Domain（业务层） 程序初始化时，Systems层会在Runtime层注册自己感兴趣的事件 当事件触发时，Runtime层会通知Systems层调用Engine层的接口来完成具体的功能实现 而Domain层则预设了各种流程，形成用户可直接用的功能。 3. # 目录结构 Source/ ├─ Core/ # 基础库（工具函数、数据结构等） │ ├─ TextFile.h/cpp # 文本读取/写入、简单热更新支持 │ ├─ Path.h/cpp # 路径处理（拼接、解析、获取程序目录等） │ ├─ Timer.h/cpp # 基础计时工具（时间间隔、时间戳） │ ├─ JsonHelper.h/cpp # JSON解析与序列化工具 │ ├─ Logger.h/cpp # 日志系统（输出到控制台/文件） │ ├─ Runtime/ # 协议层/中枢（无具体业务） │ ├─ Event/ │ │ └─ EventBus.h/cpp # 事件发布/订阅中心（模块通信核心） │ ├─ Schedule/ │ │ └─ Scheduler.h/cpp # 定时任务调度（延迟/循环任务） │ └─ State/ │ └─ StateManager.h/cpp # 全局状态管理（全局开关/配置） │ ├─ Engine/ # 系统层（操作系统交互） │ ├─ Window/ │ │ ├─ Window.h/cpp # 窗口创建、销毁、主循环管理 │ │ └─ InputRouter.h/cpp # 输入路由（分发到UI或Pet） │ ├─ Render/ │ │ └─ Renderer.h/cpp # 渲染接口封装（绘制图片/UI） │ └─ Input/ │ ├─ InputDispatcher.h/cpp # 输入捕获（鼠标/键盘事件） │ └─ InputChat.h/cpp # 文本输入处理（键盘输入解析） │ ├─ Systems/ # 业务层（核心逻辑） │ ├─ Pet/ # 桌宠系统 │ │ ├─ APetActor.h/cpp # 桌宠核心对象（状态机+组件管理） │ │ ├─ Components/ # 桌宠功能组件 │ │ │ ├─ UChatComponent.h/cpp # 控制桌宠对话内容显示 │ │ │ ├─ UAudioComponent.h/cpp # 控制音效播放 │ │ │ ├─ UDiaryComponent.h/cpp # 写入桌宠日志/日记 │ │ │ └─ UInputComponent.h/cpp # 处理用户输入内容 │ │ └─ Render/ │ │ └─ UPetRenderComponent.h/cpp # 桌宠绘制（位置/贴图/动画） │ │ │ ├─ UI/ # UI系统 │ │ ├─ AUIActor.h/cpp # UI核心对象（管理所有UI界面） │ │ ├─ Components/ # UI行为组件（交互逻辑） │ │ │ ├─ UCloseComponent.h/cpp # 关闭按钮行为（关闭程序） │ │ │ ├─ UScrollComponent.h/cpp # 滚动处理（列表/界面滚动） │ │ │ ├─ UDragComponent.h/cpp # 拖动窗口/界面 │ │ │ └─ UInputComponent.h/cpp # UI输入框处理 │ │ └─ Panels/ # UI界面（结构与渲染） │ │ ├─ UChatPanel.h/cpp # 聊天界面（显示对话） │ │ ├─ UTaskPanel.h/cpp # 任务界面（任务列表） │ │ ├─ USettingPanel.h/cpp # 设置界面 │ │ └─ UOverlayPanel.h/cpp # 浮层UI（提示/覆盖层） │ │ │ └─ Setting/ # 配置系统 │ ├─ USetting.h/cpp # 配置数据管理（读取/保存配置） │ └─ USettingWindowComponent.h/cpp # 设置窗口行为组件 │ └─ Main/ └─ AppEntry.cpp # 程序入口（初始化系统、启动主循环） # 开发规范 1.命名规范（以学习为目的，照搬虚幻引擎的命名规范） 类名：使用 PascalCase（首字母大写，每个单词首字母大写） 前缀表示类型： A → Actor，如 APetActor U → Component，如 UAudioComponent I → Interface，如 IInteractable F → Struct 或 Delegate，如 FPetStats、FOnPetClicked E → Enum，如 EPetState 成员变量：使用前缀表示类型或作用域，后接 PascalCase 名称： b → bool，如 bIsTalking i → int32，如 iHealth f → float，如 fMoveSpeed m → 成员变量，如 mCurrentState 函数 / 方法：使用 PascalCase，动词开头，清楚描述动作： 示例：PlayAudio(), MoveToTarget(), CanTalk() 文件名：与类名一致，每个类放在单独文件。 示例：APetActor.h/APetActor.cpp 2.代码风格与文件规则 每个类一个文件，文件名与类名一致。 函数名使用 PascalCase，清晰描述动作。 成员变量加前缀表示类型/作用域，保证可读性。 注释清楚描述每个模块、类、函数和复杂逻辑。 3.模块依赖规则 Core：基础工具，不能依赖其他模块。 Runtime：调度与事件管理，依赖 Core。 Engine：封装操作系统接口，依赖 Core。 Systems：业务逻辑，依赖 Core / Runtime / Engine，不被其他模块依赖。 4.事件与状态机规则 程序初始化时，各 Actor 向 EventBus 注册自己所关心的事件 程序运行时，当事件被触发后，统一进入 EventBus EventBus 根据注册关系将事件分发给对应的 Actor Actor 接收事件后，交由自身状态机判断是否执行 5.组件职责规则 每个组件只实现自身功能，不处理 Actor 以外的逻辑。 组件响应事件时必须通过 Actor 的状态机判断。 组件可以动态订阅或取消事件，但需保证在 Actor 已注册 EventBus 后执行。 #
